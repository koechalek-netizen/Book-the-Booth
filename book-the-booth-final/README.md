# 🎙️ Book the Booth — Studio Booking API

A Flask + PostgreSQL API connecting studio owners with artists, with JWT
auth, role-based authorization, deep querying, and pagination.

See [`MVC.md`](./MVC.md) for how the codebase is organized.

## Tech Stack

| Layer | Technology |
|---|---|
| Backend | Flask 3, `app/` package factory pattern |
| ORM | Flask-SQLAlchemy |
| Migrations | Flask-Migrate (Alembic) |
| Serialization | Flask-Marshmallow |
| Auth | Flask-JWT-Extended + Flask-Bcrypt |
| Database | PostgreSQL |
| Frontend | React 18 + Vite + react-router-dom (in `client/`) |

## Data Model

- **User ↔ Profile** — one-to-one
- **StudioOwner (User) ↔ Session** — one-to-many
- **Artist (User) ↔ Session** — many-to-many, via **Booking** (association
  object carrying `rate_agreed`, `session_date`, `hours_booked`, `status`)

`User` is a single table with a `role` column (`artist` / `studio_owner` /
`admin`) rather than subclasses, keeping JWT claims and role checks simple.

## Project Structure

```
book-the-booth/
├── run.py                    # entry point — imports the app factory
├── config.py                 # env-driven config (Postgres-only, fails loudly if unset)
├── extensions.py             # db, ma, jwt, bcrypt, migrate, cors — created here, bound in app/__init__.py
├── seed.py                   # populates every table + relationship with Faker data
├── requirements.txt
├── .env.example               # copy to .env and fill in — .env itself is git-ignored
├── app/
│   ├── __init__.py            # app factory + all routes
│   ├── models/                # User, Profile, Session, Booking
│   ├── controllers/           # auth, user, profile, session, booking, admin
│   ├── schemas/                # marshmallow schemas (password hash excluded)
│   ├── auth/
│   │   ├── jwt.py             # issue_token() — consistent JWT claims
│   │   └── roles.py           # @role_required() — authorization on top of @jwt_required()
│   └── utils/
│       ├── decorators.py      # @validate_json() — required-field checks
│       ├── helpers.py         # paginated_response(), error_response()
│       └── validators.py      # email/role/number validation
├── client/                    # React (Vite) frontend
└── migrations/                # generated by `flask db init` — not included here
```

> `migrations/`, `instance/*.db`, and `env/` (or `venv/`) are not committed —
> they're generated locally by the commands below. Once `migrations/` is
> generated, it *should* be committed going forward — migration scripts
> are code your teammates and CI need.

## Getting Started

### 1. Clone and enter the project

```bash
git clone <repo-url>
cd book-the-booth
```

### 2. Create and activate a virtual environment

```bash
python3 -m venv env
source env/bin/activate        # macOS / Linux
# env\Scripts\activate         # Windows
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Set up environment variables

```bash
cp .env.example .env
```

Then edit `.env` and fill in a real `DATABASE_URI` (Postgres) plus
`SECRET_KEY` / `JWT_SECRET_KEY` — generate each with:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

`config.py` raises an error on startup if any of these are missing, so you
can't accidentally run with a default secret.

### 5. Create the Postgres database

```bash
createdb book_the_booth   # or via psql / a GUI client — match DATABASE_URI
```

### 6. Initialize and run migrations

```bash
export FLASK_APP=run.py
flask db init          # only once, ever
flask db migrate -m "initial migration"
flask db upgrade
```

### 7. Seed demo data

```bash
python seed.py
```

### 8. Run the server

```bash
python run.py
```

Visit `http://127.0.0.1:5000/`.

### 9. Run the React client

```bash
cd client
npm install
npm run dev
```

## API Routes

| Method & URL | Auth | Role | Description |
|---|---|---|---|
| `POST /register` | — | — | Create a user + profile |
| `POST /login` | — | — | Returns a JWT |
| `GET /profile` | 🔒 | any | Current user's profile |
| `PUT /profile` | 🔒 | any | Update current user's profile |
| `GET /sessions` | 🔒 | any | Paginated, filterable session listings |
| `GET /sessions/<id>` | 🔒 | any | One session |
| `POST /sessions` | 🔒 | studio_owner | Create a session slot |
| `PUT /sessions/<id>` | 🔒 | studio_owner | Update a session |
| `DELETE /sessions/<id>` | 🔒 | studio_owner / admin | Remove a session |
| `GET /sessions/stats/booking-counts` | 🔒 | any | Deep query: bookings per session |
| `GET /bookings` | 🔒 | any | Current artist's paginated bookings |
| `POST /bookings` | 🔒 | artist | Reserve a session |
| `PATCH /bookings/<id>` | 🔒 | any | Confirm/cancel a booking |
| `GET /stats/revenue-by-owner` | 🔒 | admin | Deep query: revenue aggregated per studio owner |
| `GET /admin/users` | 🔒 | admin | List all users |
| `PATCH /admin/profiles/<user_id>/verify` | 🔒 | admin | Verify a studio owner account |
| `DELETE /admin/sessions/<id>` | 🔒 | admin | Moderation: remove any session |
| `DELETE /admin/bookings/<id>` | 🔒 | admin | Moderation: remove any booking |

## Migration Workflow

```bash
flask db migrate -m "message"   # detect model changes, write a migration script
flask db upgrade                # apply pending migrations
flask db downgrade              # roll back the last one
```

## Where This Repo Came From

This merges two earlier scaffolds:

- **Book-the-Booth-skeleton** — had the right domain (`User`/`Profile`/`Session`/`Booking`,
  `app/auth/`, `app/utils/`, six controllers) but every file was empty.
- **Music-Studio-Booking-App** — had working code (a real `main.py`, a live
  React client) but for an older domain (`Studio`/`Equipment`, no roles, no `Profile`).

This repo keeps the working scaffolding pattern from the second and the
correct domain model from the first.
